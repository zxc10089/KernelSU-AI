# AI 控制台 · 使用指南

AI 控制台是管理器内置的对话式助手。用自然语言说明想检查或处理的事情，助手会读取设备信息、模块目录与 root 授权记录，给出结论和一份「准备做什么」的动作清单；**动作不在模型一侧执行**，而是由管理器在本机逐条执行，写入、删除、改权限这类动作在执行前必须由用户点确认。

AI 真正改动过设备的动作都会写入「AI 操作历史」，可以回看，其中一部分还能撤销。这本账只记录 AI 的动作：你自己在设置页修改访问范围不会出现在这张列表里。

需要准备的东西：一台已经获取 root 的 KernelSU 设备、一个 AI 服务的 API 密钥、可用的网络。

---

## 一、功能概览

### 能做什么

- **对话**：描述需求（例如「看看哪个应用拿着 root 权限不合理」「检查模块之间有没有冲突」），助手给出结论，必要时附带动作。
- **本地执行**：读文件、列目录、搜索内容、执行只读命令、启停模块、授予或撤销 root、把文件移入回收站、生成并安装模块，都由管理器在本机完成。
- **执行前审查**：每个动作先经过本地闸门判定，得到「自动执行 / 需要确认 / 高危操作」三个等级之一；被判定为超出当前授权范围的动作会被直接拒绝，不会执行。
- **计划模式**：先让助手把完整计划列出来，可编辑，再一键执行。
- **日志与历史**：会话里有客户端日志面板，另有独立的操作历史页面记录 AI 实际执行过的改动，并支持撤销。
- **两个附带页面**：root 权限审查、模块冲突检测。

### 从哪里进入

| 入口 | 位置 | 打开的内容 |
| --- | --- | --- |
| 主页卡片「接入 AI 助手」 | 主页 | 模型与参数配置页；配置完成后从页内「进入 AI 控制台」 |
| 超级用户页 | 超级用户页顶栏 | AI 控制台，并自动带上一次 root 权限审查的提问 |
| 模块页 → 模块制作 →「让 AI 起草」 | 模块制作页 | AI 控制台，自动切到计划模式并发出起草模块的请求 |
| 模块页 → 检查模块冲突 →「让 AI 解读」 | 模块冲突检测页 | AI 控制台，并带上扫描 `/data/adb/modules` 的提问 |
| 超级用户页 →「AI 权限审查」 | 超级用户页顶栏 | AI 权限审查页，其中「在控制台深入审查」进入控制台 |
| 控制台标题栏 | AI 控制台 | AI 操作历史 |

注意主页卡片进入的是**配置页**，不是控制台；只有配置过参数后，才能从配置页进入控制台。

### 一次对话里会发生什么

1. 输入内容并发送。若尚未配置模型，输入区会提示「尚未配置模型」。
2. 管理器把对话历史与当前的访问范围、Shell 开关、计划模式状态一起发给模型，状态行显示为「访问范围 … · shell 开/关」。
3. 模型以固定 JSON 结构回复：一段结论 + 一组动作。
4. 动作逐个经过本地闸门：自动执行的动作直接执行；需要确认的动作弹出确认框；高危动作弹红色确认框；越界的动作显示为「已拦截」。
5. 执行结果回传给模型，进入下一轮，直到模型不再提出动作，或达到「最大轮次」。

### 界面上的状态词

| 状态 | 含义 |
| --- | --- |
| 待确认 | 动作已列出，尚未开始处理 |
| 等待你的确认 | 正在等确认框的答复 |
| 执行中 | 本地正在执行 |
| 已完成 | 执行成功 |
| 执行失败 | 执行报错，卡片上会附输出 |
| 已拦截 | 被本地闸门拒绝，未执行 |
| 已取消 | 在确认框里点了取消 |
| 已跳过 | 计划在更早的步骤暂停，本步没有执行 |

动作卡上的等级标签为「自动执行 / 需要确认 / 高危操作」。

## 二、首次配置

路径：主页「接入 AI 助手」卡片 →「模型与参数配置」。该页只保存参数、拉取模型列表、设置文件访问范围；它本身不会执行任何命令。

### 2.1 API 设置

| 字段 | 说明 |
| --- | --- |
| API 提供商 | 从预设列表选择；选定后会按预设填入端点与示例模型名 |
| API 端点 | 完整的对话补全地址，必须以 `http://` 或 `https://` 开头，否则会提示「端点需以 http:// 或 https:// 开头」 |
| API 密钥 | 可显示/隐藏；只需要端点和模型名即可进入控制台，密钥可以为空（例如本地服务） |
| 模型名称 | 手动填写，或用「获取模型列表」从服务端拉取后选择 |
| 获取模型列表 | 按当前端点请求模型清单，弹层内可选择、搜索、重试 |

提供商列表按「推荐 / 核心」「本地 / 私有」「其他国内外」三组排列，带「推荐」徽标。选中某个提供商时填入的端点是**预设值，不是唯一答案**，改成服务商提供的地址即可：

| 提供商 | 预设端点 | 示例模型名 |
| --- | --- | --- |
| Deepseek 大模型 | `https://api.deepseek.com/v1/chat/completions` | deepseek-chat |
| OpenAI 兼容 | 不预填，自行填写 | gpt-4o-mini |
| Anthropic 通用 | `https://api.anthropic.com/v1/messages` | claude-3-5-sonnet-latest |
| OpenAI（GPT 系列） | `https://api.openai.com/v1/chat/completions` | gpt-4o、gpt-4o-mini |
| Ollama（本地） | `http://127.0.0.1:11434/v1/chat/completions` | llama3.1、qwen2.5 |
| LM Studio（本地） | `http://127.0.0.1:1234/v1/chat/completions` | local-model |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | glm-4-plus |
| 通义 | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | qwen-plus |
| 文心 | `https://qianfan.baidubce.com/v2/chat/completions` | ernie-4.5-turbo |
| 星火 | `https://spark-api-open.xf-yun.com/v1/chat/completions` | generalv3.5 |
| Gemini | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` | gemini-2.0-flash |

端点格式取决于提供商家族，选择提供商时已经确定：

- **OpenAI 兼容类**（Deepseek、OpenAI、Ollama、LM Studio、智谱、通义、文心、星火、Gemini 的兼容入口）：请求发往 `<端点>`，认证使用 `Authorization: Bearer <密钥>` 请求头。
- **Anthropic**：默认端点为 `https://api.anthropic.com/v1/messages`，认证使用 `x-api-key` 请求头。

若不使用「获取模型列表」，模型名必须与服务商的模型标识一致，否则服务端会返回错误。拉取模型列表时，管理器会根据端点推断清单地址：去掉末端的 `/chat/completions`、`/completions` 或 `/messages` 后拼上 `/models`；端点本身以 `/models` 结尾时原样使用。

### 2.2 权限与执行安全

「快捷策略模板」一次设置两个开关（Shell 开关与文件访问范围），选择后仍可在下方单独调整；之后把范围调高时依然会走确认门。

| 模板 | Shell 命令 | 访问范围 |
| --- | --- | --- |
| 严格只读 | 关闭 | 允许访问 `/data/adb/` |
| 智能助手 | 开启 | 允许访问 `/data/adb/` |
| 极客模式 | 开启 | 允许访问根目录 `/` |

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 允许 AI 执行 Shell 命令 | 关闭 | 未开启前不会执行任何命令；关闭时即使模型提出命令，也会被本地闸门拒绝并提示「Shell 执行已关闭，请先在配置页打开」 |
| 执行高危命令前强制确认 | 锁定开启 | 高危命令绝不会在未确认的情况下执行，此项不可关闭 |
| 允许 AI 读取和修改模块目录 | 关闭 | 早期版本的开关；当前版本由「AI 访问范围」统一控制。旧配置中该项为开启时，会作为 `/data/adb/` 范围的兼容来源 |

### 2.3 对话参数与预估消耗

| 参数 | 默认值 | 可选范围 | 作用 |
| --- | --- | --- | --- |
| 最大轮次 | 50 | 1–100 | 一条消息最多与模型交互几轮；每个动作的执行结果都会作为下一轮的输入 |
| 单次读取上限 | 128000 字符 | 500–256000 | 每次读取最多回传给模型的字符数；到达上限即停，并在末尾给出续读位置 |
| 全量读取阈值 | 2048 KB | 8–4096 | 不超过该大小的文件一次读完；更大的文件只回传一段，需续读或用文件内搜索 |

页面上会给出该配置下的最坏情况用量估算，单位为万 Token，并附一个粗略费用参考。用量与端点、模型的实际计费无关，仅供取舍参考。

### 2.4 配置保存在哪里

配置保存在管理器自己的偏好文件中（键名为 `ai_settings`，与界面偏好分开存放），包含提供商、端点、密钥、模型名、Shell 开关、访问范围与上面三个参数。该文件是应用私有目录下的明文 XML，**在 root 设备上任何以 root 运行的程序都能读取它**，不要把它当作安全存储；建议使用可以随时吊销、限额的密钥。

## 三、AI 访问范围

「AI 访问范围」控制助手可以读写哪些文件。默认是「禁止访问」，即收紧优先。

| 档位 | 助手能做什么 |
| --- | --- |
| 禁止访问 | 不能读取或修改任何文件；对话、设备信息、root 授权列表与权限审查仍然可用 |
| 允许访问 `/data/adb/` | 可读取和修改 `/data/adb` 及其子目录下的内容，包含模块目录；`/data/adb` 之外的路径会被直接拒绝 |
| 允许访问根目录 `/` | 可读取任意路径；写入与删除仍会被判定为最高风险并要求单独确认 |

档位越高，助手能看到和改动的范围越大。中间档覆盖的是 root 管理相关的数据目录；最高档意味着设备上任何可读文件都在助手视野内。

### 提升范围时的确认

从低档提升到高档（或从「禁止访问」直接跳到「允许访问根目录 /」）会弹出确认框：

- 标题：「提升 AI 访问范围？」
- 正文：「提升后，AI 将可以读取和修改：<目标档位说明>」
- 按钮：「取消」/「确认提升」

单击即可确定，无需输入任何确认内容。降低范围不弹确认，直接生效。会话顶部的状态行会显示当前范围。

### 范围与 root 授权的关系

授予或撤销应用 root 权限、启停模块、安装模块这类动作走的是管理器原有的 root 接口，**不受文件访问范围限制**，任何档位下都可以执行；它们由确认门把关。范围只决定文件系统相关动作的边界。

### 范围也决定了两个附带页面

- 模块冲突检测需要「允许访问 `/data/adb/`」及以上，否则页面提示「模块扫描需要访问 /data/adb/，请先到 AI 助手配置页提升范围。」
- 权限审查本身不需要文件访问。

## 四、需要确认的危险操作

### 三个等级

| 等级 | 界面含义 | 处理方式 |
| --- | --- | --- |
| 自动执行 | 只读且无副作用 | 直接执行，日志里记为「静默执行」 |
| 需要确认 | 会改变设备状态 | 弹出应用通用确认框，标题为「确认操作」，正文是动作名与具体参数 |
| 高危操作 | 可能影响系统或不可逆 | 弹出红色确认框 |

对照关系：

- **自动执行**：读取文件、列出目录、分段读取、文件内搜索、查看文件信息；root 授权列表；设备信息命令（`id`、`uname`、`uptime`、`getprop`、`getenforce`、`whoami`）；只读文件命令（`ls`、`cat`、`head`、`tail`、`df`、`du`、`stat`、`find`、`grep`、`wc`、`readlink`、`realpath`、`file`）；`pm list`、`dumpsys` 的常用子命令、`logcat -d`、`ksud module list`、`ksud su list`。
- **需要确认**：只读查询（`safe_exec_shell` 白名单内的查询命令）；授予 root 权限、撤销 root 权限；启用模块、停用模块、安装模块；`ksud module enable/disable/install/uninstall/action`。
- **高危操作**：移入回收站；制作模块；无法识别的动作；`rm`、`dd`、`mount`、`chmod`、`cp`、`mv`、`sh`、`su` 等会改动系统的命令；命令里出现引号、管道、重定向或通配符；`find` 带删除或执行类参数；不在允许清单内的命令；以及**同一轮里出现 3 个及以上动作时的批量升级**。

### 红色确认框

标题为「⚠️ 确认执行系统命令」，正文为「AI 正在尝试调用 Root 权限，请确认是否执行以下操作：」，下面以等宽的终端样式区块列出动作名与完整参数（模块动作会列出模块 id、名称、版本、文件清单，并额外提示其中带有 `customize.sh`，安装时会以 root 执行）。区块下方是红色提示语：默认「该操作可能修改系统核心文件，请谨慎确认。」，只读命令显示「只读操作：这条命令不会修改设备。」按钮为「取消」/「确认执行」。

确认框只要求单击一次，不要求输入任何确认词。但单击即代表执行，红色弹窗里的参数建议逐条核对，尤其是路径与模块 id。

### 取消与中止

- 在确认框里点「取消」：该动作记为「已取消」，本轮其余动作继续处理。
- 点输入框旁的「停止」：中断当前回合，日志记录「用户停止了本轮执行」。
- 「清空对话」会二次确认，确认后删除当前会话的全部消息与客户端日志；如果 AI 正在回复，本轮也会停止。

## 五、计划模式

输入框上方的「对话模式 / 计划模式」胶囊可以切换当前模式，切换会写进日志（「已切换到计划模式：先出计划，一键批准后统一执行」/「已切换到对话模式：动作按顺序执行」）。

计划模式下的流程：

1. 发送需求后，助手只给计划、不动手。会话里出现「📋 任务计划」卡片，徽标为「待批准」，每一步显示为「待确认」，卡片下方说明「共 N 步 · 只读动作批准后直接执行，写入仍会单独确认」。
2. 卡片按钮为「修改计划」「一键执行全部」「中止」。
   - 「修改计划」：丢弃该计划，并把「请调整上面的计划：」预填进输入框，等待补充说明。
   - 「一键执行全部」：按顺序执行计划中的动作。只读动作自动放行；写入、删除、root 授权等仍然逐个弹出确认框。
   - 「中止」：丢弃计划，会话中记录「用户中止了这个计划，其余步骤没有执行。」
3. 某一步失败或被拒绝时，计划暂停，卡片变为「已暂停」，该步之后的步骤标记为「已跳过」，日志记录暂停原因；「修改计划」与「中止」仍可用。

计划模式**不会**因为「一键执行全部」而跳过确认门：批量执行只是把动作排队，危险动作照样逐条确认。

## 六、日志与历史

### 6.1 客户端日志

控制台内可展开「客户端日志」面板，内容来自 AI 执行日志（前缀为 `[AI_AGENT]`），包括：每轮发送的消息条数与目标模型、模型提出的动作数量、闸门判定结果（静默执行 / 等待确认 / 拒绝原因）、执行成功或失败、计划模式的切换与暂停、达到最大轮次等。日志只存在于本次会话的内存中，关闭管理器后消失。

### 6.2 操作历史与撤销

控制台标题栏进入「AI 操作历史」。列表按时间倒序显示 **AI** 实际执行过的动作，每条包含时间、类型、目标与结果（成功 / 失败 / 已拒绝），点开可查看完整字段：时间、类型、目标、之前、之后、命令、范围、结果。你在设置页修改「AI 访问范围」属于用户操作，会写入同一份账本用于恢复，但**不在这张列表里显示**。

- 时间戳格式为 `MM-DD HH:MM:SS`，例如 `移入回收站 成功 /data/adb/modules_update/<模块 id>`。
- 可撤销的记录带「撤销」按钮，点击后弹出「撤销该操作？/ 将 <路径> 恢复到之前的状态。」。撤销动作本身会作为一条新记录写入历史，结果记为新记录的「成功/失败」，原记录归入已撤销。
- 目前支持撤销的类型：root 授权（授予↔撤销）、模块启停、移入回收站（移回原位置）。模块制作、模块安装等不提供撤销，页面会提示「该记录不支持撤销」；访问范围变更不在这张列表里，也不提供一键还原，如需回退请在配置页重新选择档位（升档仍需确认）。
- 没有记录时显示「暂无操作记录」。

删除类动作**不是**真正删除：执行器会把目标移动到 AI 回收站目录 `/data/adb/.ai_trash`，因此可以从操作历史撤销。历史记录写在应用私有目录下的 `ai_audit.jsonl`，一行一条 JSON，最多保留最近 2000 条；它只记录动作本身，不记录聊天内容与 API 密钥。

## 七、常见问题与限制

### 配置与网络

| 现象 | 原因与处理 |
| --- | --- |
| 请求失败：HTTP 401 | 密钥无效或未随请求发送；核对提供商与密钥 |
| 请求失败：HTTP 429 | 触发服务商限流；降低轮次或稍后重试 |
| 请求失败：HTTP 400 | 模型名或请求体不被接受；核对模型名是否与服务端一致 |
| 响应格式无法解析 | 服务端返回的不是预期的对话结果；确认端点指向对话补全地址，且服务商协议与所选家族一致 |
| 网络错误 | 断网、超时或代理问题；管理器对单次请求的超时较长，推理型模型首字节可能等待较久 |
| 请先配置 API 参数 / 尚未配置模型 | 端点或模型名为空；到配置页补齐 |
| 已达最大轮次 50 | 达到「最大轮次」上限；可在配置页调高，或把需求拆小 |

### 被本地闸门拒绝时的提示原文

| 提示 | 处理 |
| --- | --- |
| 超出当前授权范围 | 动作落在当前访问范围之外；到配置页提升范围，或改用范围内的路径 |
| 命令访问了授权范围之外的路径 | 命令中出现了范围外的路径；同上 |
| 命令会读取授权范围之外的目录树 | 递归类命令会越界；缩小为具体路径 |
| 文件访问已关闭，请先在配置页选择访问范围 | 当前是「禁止访问」；需要文件操作时改为具体档位 |
| Shell 执行已关闭，请先在配置页打开 | 打开「允许 AI 执行 Shell 命令」 |
| 该命令不在允许的只读命令清单里 | 命令不在白名单内；只读查询请使用清单内的命令 |
| 命令包含引号、管道、重定向或通配符，只允许单条简单命令 | 一次只允许一条不带这些符号的命令 |
| 路径为空 / 命令为空 / 命令过长 | 参数不合法；单条命令有长度上限 |
| 已取消 / 已拦截 | 分别是用户取消与闸门拒绝，都不会执行 |

### 附件

输入框左侧的回形针可以「添加附件」：

- 文本类（`.txt`、`.log`）单个文件上限 8 MB，超过 64000 字符的部分会被截断。
- 图片（`.png`、`.jpg`、`.jpeg`）上限 5 MB，按像素随消息发送。
- 压缩包（`.zip`）。
- 其他扩展名不支持，会提示「不支持的文件类型」；超限提示「文件过大（上限 8 MB）」或「图片过大（上限 5 MB）」；读取失败提示「无法读取文件」。

### 模块制作

- 模块制作页各字段为：模块 ID、模块名称、版本、版本代号、作者、描述、文件（相对路径 + 内容）、安装脚本（`customize.sh`）、包内文件预览。
- 限制：模块 ID 以字母开头、至少 2 个字符；文件数量上限 20 个、单文件 64 KB、总量 128 KB；相对路径不得包含 `..`。
- 「生成安装包」在应用缓存目录生成 zip；「安装模块」把包安装到 `/data/adb/modules_update`，提示「重启后生效。」，安装结果输出显示在「安装器输出」中。
- 从控制台侧发起时，模块制作页顶部会显示「这份草稿来自 AI 控制台；安装前请先核对 id 与文件清单。」；执行安装前务必核对 id 与文件清单，特别是脚本内容。

### 其他限制

- **会话不持久化**：对话消息与客户端日志只保存在内存中，进程结束后清空；操作历史不受影响，仍然保留。
- **模块安装不即时生效**：安装到 `/data/adb/modules_update`，需重启后生效；助手不会直接改写系统模块目录。
- **写入始终需要确认**：即使选择「允许访问根目录 /」，每一次写入与删除仍然单独确认。
- **辅助页面需要 root**：权限审查与模块冲突检测都依赖设备的 root 状态；冲突扫描一次最多处理 200 个启用模块、每个模块最多 2000 个文件、最多报告 200 条冲突。
- **权限审查的分级**只针对管理器已知的授权配置：uid 低于系统阈值、具备额外 capability 或用户组的应用列为「高风险」；使用自定义 root 配置、root 模板，或不卸载模块（root 痕迹可被该应用看到）、无应用名称的列为「需留意」；其余「低风险」。「撤销」会立即收回该应用的 root 权限，且这次撤销可以在操作历史里再撤销回来。
